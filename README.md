A structured, hands-on record of vulnerability assessment work performed against self-hosted, intentionally vulnerable targets (DVWA, PortSwigger Web Security Academy), mapped to the **OWASP Top 10 (2021)**. Every finding in this repository was manually exploited, verified, and root-caused — not generated by an automated scanner and pasted in.

Each write-up follows a consistent, industry-style structure:
**Overview → Environment → Methodology / Steps to Reproduce → Why It Worked → Impact → Remediation**

This mirrors the structure of a real penetration testing / vulnerability assessment report, and is intended as a working portfolio for cybersecurity roles (SOC Analyst, Application Security, Penetration Testing Intern).

## 🔑 Highlights

- **Networking fundamentals** — captured and correctly interpreted a TCP 3-way handshake vs. a closed-port rejection, then cross-verified an Nmap version-detection scan (`-sV`) against raw packet data rather than trusting tool output blindly.
- **SQL Injection** — bypassed login logic, performed UNION-based extraction of usernames and password hashes, then cracked a captured MD5 hash offline with John the Ripper after troubleshooting a GPU/OpenCL limitation with hashcat.
- **Cross-Site Scripting** — exploited all three major XSS classes (Reflected, Stored, DOM-based), including a case-sensitivity filter bypass at DVWA's Medium security level, and demonstrated session cookie exposure via a simulated theft payload.
- **Security Misconfiguration** — identified four independent misconfigurations on one target (default credentials, exposed debug info, verbose SQL errors, missing security headers), including a PHP runtime over six years past end-of-life.
- **Cryptographic Failures** — identified MD5/SHA-1/SHA-256/bcrypt purely by hash format, cracked the fast hashes instantly, then proved bcrypt's per-call salting produces a different output for an identical password every time — and captured a live DVWA login in Wireshark showing both the password and session cookie transmitted in plaintext over HTTP.
- **Vulnerable & Outdated Components** — mapped a PHP 7.0.30 end-of-life finding to a real, named CVE (CVE-2018-10549) and a concrete, reachable attack surface (DVWA's File Upload / EXIF parsing path), rather than stopping at "the version is old."
- **Identification & Authentication Failures** — cracked credentials via automated Hydra brute force (diagnosing two real field-parsing syntax errors along the way), proved a server-side `sleep()` delay is defeated by Hydra's default thread concurrency, executed a full cross-browser **session fixation** attack authenticating a session with zero credentials entered, and compared session-ID generation source code across four security tiers to show that hashing a predictable counter adds no real entropy.
- **Security Logging & Monitoring Failures** — live-tailed Apache logs during manual and automated brute-force attempts, diagnosed a false positive *and* false negative in Hydra's detection logic (root-caused to DVWA's CSRF token via debug-mode traffic inspection), then executed a real CSRF exploit that silently changed the admin password and produced a near-invisible log signature — directly contrasted against the loud, tool-fingerprinted brute-force traffic.
- **Server-Side Request Forgery** — used Burp Suite (first hands-on session with the tool) to intercept and rewrite a server-side `stockApi` parameter, redirecting an internal server-side fetch to `localhost/admin/delete?username=carlos` to fully bypass access control on a live PortSwigger lab. A second, hardened lab with server-side URL validation was attempted and is documented as in-progress, including the exact rejection response received.

## 🧠 Methodology

Every write-up in this repository follows the same investigative pattern, regardless of vulnerability class:

1. **Reconnaissance** — inspect the target's actual behavior and source (where available) before attempting exploitation; never assume.
2. **Exploitation** — perform the attack manually first to understand the mechanism, then automate where appropriate (Hydra, scripted payloads).
3. **Verification** — independently confirm every result (e.g., logging back in with a cracked password, re-reading a cookie value) rather than trusting a tool's success message at face value.
4. **Root Cause** — read the relevant backend source code where accessible to explain *why* the vulnerability exists, not just that it does.
5. **Impact & Fix** — translate the technical finding into business impact and a concrete, actionable remediation.
